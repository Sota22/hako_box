## 量子将棋

すべての駒が「玉・飛・角・金・銀・桂・香・歩のどれか分からない」状態から始まる将棋です。
駒を動かすと、その動きができる種類に正体が絞られます（観測）。相手の「玉でしかありえない駒」を取ったら勝ち。

- スマホのブラウザで遊べる1ファイルの HTML（`docs/index.html`）
- AI 対戦（先手／後手、考える時間4段階）と 2人対戦
- AI は Web Worker 上で反復深化 αβ 探索（置換表・静止探索・ヌルムーブ・LMR）

### 構成

| ファイル | 内容 |
|---|---|
| `src/engine.js` | ルール判定と AI。陣営の駒構成との矛盾は Hall の定理で判定 |
| `src/app.js` | 画面と操作 |
| `src/style.css`, `src/template.html` | 見た目 |

```

## 将棋対囲碁

駒を動かす将棋側と、石を置く囲碁側が 9×9 の盤で戦います（将棋盤の81升 = 9路盤の81か所）。

- 将棋側: 駒の並べ方・動き・成りは将棋と同じ。石の上に動くと石を取る。石を規定数取れば勝ち。
- 囲碁側: 空き升に石を置く。呼吸点がなくなった駒の連を取る（囲碁と同じ）。玉を取れば勝ち。
- 将棋側も、石の連を駒で囲めば取れる。自殺手は双方禁止。
- 互角にするための調整（元のルールから変えたところ）
  - 囲碁側は1手番に石を2つ置く（最初の手番だけ1つ）
  - 囲碁側の石は碁笥の100個まで。置き終えたら終局し、囲碁と同じく地（自分の石・駒＋自分だけに囲まれた空き升）を数える
  - 将棋側の目標は石37個（AI 同士の対局で勝率が半々に近くなる値）

### 調整の記録（AI 同士の対局）

| ルール | 結果 |
|---|---|
| 元のまま（囲碁側は1手番に1つ） | 将棋側の目標を45個にしても将棋側が8戦全勝。駒が毎手1つずつ石を取れるため |
| 囲碁側は1手番に2つ | 目標を80個にしても将棋側が約70%（1手1秒）。囲碁側は序盤に玉を囲めないと、その後は石を食べられ続ける |
| 囲碁側は1手番に3つ | 将棋側81%。盤上の石が増えて、将棋側に大きな連ごと囲まれて取られる |
| 1手番に2つ＋碁笥100個（置き終えたら地を数える） | 目標40個で将棋側28%（32局）、35個で65%（48局）、**37個で54%（48局）** ← 採用 |

勝率はすべて AI 同士・1手1秒。37個のとき、囲碁側の勝ちは玉を囲んで19局・地で3局、将棋側の勝ちは石37個で26局。

AI の評価関数も、自己対局で強くなった値を側ごとに使っている（`PARAMS.bySide`）。

| ファイル | 内容 |
|---|---|
| `shogi-vs-go/src/engine.js` | ルール判定と AI（反復深化 αβ、置換表、静止探索） |
| `shogi-vs-go/src/app.js` | 画面と操作 |
| `shogi-vs-go/build.js` | `docs/shogi-vs-go/index.html` と `dist/shogi-vs-go.html` を生成 |
| `shogi-vs-go/test/smoke.js` | ランダム対局でルールの不変条件を確認 |
| `shogi-vs-go/test/selfplay.js` | AI 同士の対局で勝率を測る |
| `shogi-vs-go/test/estimate.js` | 対局の記録から、目標の数を変えたときの勝率を見積もる |

node shogi-vs-go/build.js
node shogi-vs-go/test/smoke.js
node shogi-vs-go/test/selfplay.js '{"goal":37}' 48 1000   # AI 同士 48局（1手1秒）
```
